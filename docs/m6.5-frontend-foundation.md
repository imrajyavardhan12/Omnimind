# M6.5 — Frontend Foundation (scope)

Status: LOCKED · Created 2026-06-02 · Branch `m6.5-frontend-foundation` off `main` @356c9b7

## Objective

Turn the backend-run chat view from a *grafted-onto-MVP* surface into a **clean,
consistent, dogfoodable** product shell — so single + compare chat is something you'd use
daily, and so M7 (files) and M8 (council) plug into a solid frontend instead of compounding
UI debt.

This is **not a rewrite**. The run engine, data model, gateway, SSE protocol, and all API
contracts are FROZEN. M6.5 touches presentation and thin client wiring only.

## Why now (the evidence)

The M6 live click-through found 1 CORS defect + 8 bugs. **Every one was presentation layer
or thin-client wiring — zero in the backend.** The frontend is the one layer that never got
the architectural rigor the backend did. Patch-by-patch has hit its limit (each fix is
minimal, the shell stays MVP, so it still *feels* buggy). Do one deliberate, bounded
foundation pass, then dogfood — before piling M7/M8 UI on top.

## In scope

1. **Unified app shell** — one consistent chrome for single + compare; remove the grafted
   MVP header/controls that don't belong on the run path; coherent layout.
2. **Backend-wired conversation sidebar** — a proper left rail (replaces the interim header
   dropdown + the hidden legacy localStorage sidebar), reading `GET /v1/conversations`:
   **list · select** (resets in-flight run, loads history) **· new · delete**. Rename = deferred.
3. **Owned streaming renderer** — promote the patched `MarkdownRenderer` into a
   deliberately-owned, documented streaming-grade component for the run path (so it no longer
   rides the legacy MVP component's quirks). Clean code-block rendering mid-stream.
4. **Light-but-tasteful visual pass** — a real primitive set (buttons / inputs / panels,
   type scale, spacing) applied consistently, adopting the shadcn-style primitives the docs
   already call for (`22-product-ux-principles.md`). A *foundation*, not lipstick — but within
   the current look, NOT a redesign.
5. **Retire the single/compare dual-path** — remove the `chatRunsEnabled` flag + the flag-OFF
   legacy components (`SingleChatInterface`, `AnimatedUnifiedInput`, `DynamicChatPanel`) from
   the page; `RunChatView` becomes the only path. **Gated on the M6 re-test passing; done LAST.**
   Keep the legacy stores/route Council + prompt-enhancer still import (they die in M8).
6. **Frontend-standards doc** (`docs/architecture/06b-frontend-standards.md`) — written DURING
   the build: run-view component structure, state ownership (server=TanStack, UI=Zustand,
   stream=`useChatRun`), streaming-render rules, per-feature API-client pattern, the
   reconciliation invariant. The enforced rigor the frontend lacked.

## Explicitly OUT of scope

- M7 file-upload UI, M8 council UI, or ANY new feature surface.
- A full visual redesign / rebrand / theming system (its own milestone, after dogfooding).
- **Observability** — request logger / error surfacing done *opportunistically*, not a scope
  item; real observability (Sentry / Langfuse / OTel) is M9.
- Mobile-specific redesign (noted as later).
- Any backend contract change (engine / gateway / data model / SSE are frozen).
- Migrating Council / prompt-enhancer off the legacy stores (that's M8).

## Work breakdown (ordered to sequence risk)

1. Finish the **M6 pending re-test** (streaming code-block render, multi-turn no-vanish,
   cancel/disconnect→send-again, response-language, Council shared-renderer sanity). GATES step 6.
2. **Conversation sidebar** (real left rail; list/select/new/delete) — replaces the interim dropdown.
3. **Shell consolidation + tasteful visual pass** — coherent chrome, consistent primitives.
4. **Own + document the streaming renderer.**
5. **Retire the dual-path** — remove flag + legacy components (grep importers first; some are
   shared with Council). LAST, after step 1 passes.
6. **Write the frontend-standards doc** — codify the patterns established in 2–4.

## Exit criteria (the "done" gate)

- `RunChatView` is the only single/compare path; flag + legacy single/compare UI removed; build clean.
- Conversation sidebar lists backend conversations; select / new / delete work; no stale-panel leaks.
- Streaming renderer is owned + documented; code blocks render cleanly during streaming.
- One consistent, tasteful shell; no dead/lying controls anywhere in run mode.
- `frontend-standards` doc committed.
- Gates green (type-check / lint / test / build); the M6 re-test list passes.
- **The honest test: "Would I use this as my daily multi-model chat?" → yes.**

## Guardrails (anti-balloon)

- Time-box it. If the visual pass starts creeping toward a redesign — STOP; separate milestone.
- No feature UI. If a task needs an M7/M8 surface, it's out of scope.
- Don't touch backend contracts. If a fix seems to need one, the boundary is wrong, not the contract.
- Before deleting any legacy component, grep its importers (Council/enhancer may share it).

## After M6.5

**Dogfood the core** for ~a week before sequencing M7 (files) / M8 (council) / M9 — let real
usage set the order, not the fixed plan. See `docs/handoff-m6.md` addendum and
`docs/master-rebuild-plan.md`.
